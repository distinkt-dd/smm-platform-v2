# Graphify в проекте

Для навигации по исходному коду backend и frontend используем Graphify вместо отдельной карты кода. Граф хранится в [graph.json](../graphify-out/graph.json); интерактивная визуализация — [graph.html](../graphify-out/graph.html), сводка — [GRAPH_REPORT.md](../graphify-out/GRAPH_REPORT.md). Откройте HTML локально в браузере. Описание контрактов, проверок и точек входа остаётся в [структуре приложений](foundation.md).

В Codex навык устанавливается глобально в `~/.codex/skills/graphify` и вызывается как `$graphify`. Команда `graphify` устанавливается отдельно. На Windows после изменения PATH может понадобиться перезапустить терминал или приложение.

Из корня проекта примеры запросов:

```sh
graphify query "ProfileService ServicesList"
graphify explain "ProfileService"
graphify path "ProfileController" "ProfileService"
```

При изменении кода обновите граф и сводку из корня проекта:

```sh
graphify extract . --code-only
graphify cluster-only . --no-label
```

При намеренном удалении кода и отказе Graphify перезаписать уменьшившийся граф используйте `graphify extract . --code-only --force`, затем повторите `cluster-only`. В Git сохраняются граф, HTML и отчёт; локальный кэш, служебные файлы и абсолютные пути исключены. Для SQL-миграций нужен пакет `graphifyy[sql]`, для команд запроса в текущей версии также нужен `graphifyy[mcp]`.

Граф построен локальным структурным анализом кода и SQL, без семантического анализа документов и изображений. Он не гарантирует полное покрытие: отдельные файлы и связи могут не распознаваться, сгенерированные и игнорируемые Git файлы исключены. Связи `INFERRED` являются предположениями. Проверяйте вывод по исходным файлам, а поведение и контракты — по коду, тестам и документации. При изменении контракта, точек входа или проверок обновляйте и описание структуры приложений.
