# Архитектурные решения

Дмитрий выбирает стек, структуру приложения и контракты по мере разработки. Здесь фиксируется каждое существенное решение v2 с датой, статусом, формулировкой и причиной.

| Дата | Статус | Решение | Причина |
| --- | --- | --- | --- |
| 2026-11-16 | Принято | Использовать Docker Desktop для периодических проверок почти готовых модулей. | Воспроизводить условия развёртывания на VPS к концу работы над модулем. |
| 2026-11-16 | Принято | Отдельные npm-приложения: NestJS на backend и React + Vite + Tailwind CSS на frontend; базовые зависимости — по проекту SMM в кармане. | Использовать знакомый стек для новой версии продукта. |
| 2026-11-17 | Принято | Задачи и доску агент ведёт через GitHub MCP Server, подключённый к DeepSeek Harness бандлом `@local/dsh-github-mcp`. Токен хранится в хранилище DSH под именем `GITHUB_PERSONAL_ACCESS_TOKEN`. | Дать агенту прямое управление Issues и Projects V2 вместо ручных операций Дмитрия. |
| 2026-11-18 | Принято | Готовность базы backend проверяет запросом `SELECT 1` при старте и в `GET /health`; при недоступной базе приложение стартует, пишет ошибку в лог и отвечает `503` на проверку готовности. | `$connect()` в режиме driver adapter соединение не устанавливает: пул `pg` подключается лениво, поэтому лог о подключении без реального запроса вводил в заблуждение. |
| 2026-11-19 | Принято | На frontend слои FSD упорядочены сверху вниз `pages` → `widgets` → `shared`; layouts относятся к слою `pages` (`frontend/src/pages/layouts`), `shared` не импортирует `widgets` и `pages`. | Layout в `shared` импортировал виджет и нарушал направление зависимостей FSD. |
| 2026-11-23 | Принято | Базовый транспорт frontend размещается в `shared/api` и использует нативный `fetch`; пути `/auth/register`, `/auth/login` и `/auth/me` задаются константами, адрес backend берётся из `VITE_API_URL`, токен передаётся в параметры запроса. | Получить общую типизированную основу для API без дополнительной зависимости и без привязки транспорта к хранению состояния авторизации. |
| 2026-11-23 | Принято | Добавить слой `entities` между `widgets` и `shared`; первый модуль `entities/auth` содержит методы авторизации и типы их запросов и ответов. | Выделить API авторизации из общего транспорта и соблюдать направление зависимостей FSD. |
