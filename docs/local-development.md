# Локальные проверки и Docker Desktop

Дмитрий выполняет проверки на своём компьютере и сам запускает, перезапускает и останавливает контейнеры. Перед проверкой Codex объясняет, из какой папки запустить команду, что она проверяет и по какому выводу определить успех. Если команда завершилась ошибкой, Дмитрий передаёт команду и текст ошибки, а Codex помогает найти причину и выбрать следующий шаг.

В задаче или PR Дмитрий фиксирует, какие команды запустил, что прошло, где возникли ошибки и какие сценарии ещё предстоит проверить. Codex использует эти результаты при ревью.

## Проверки без Docker

После установки зависимостей через `npm ci` в каталоге соответствующего приложения выбери команды под задачу.

| Каталог | Команда | Что проверяет |
| --- | --- | --- |
| `backend` | `npm test` | Запускает модульные тесты. |
| `backend` | `npm run test:e2e` | Запускает сквозные тесты backend. |
| `backend`, `frontend` | `npm run build` | Собирает приложение в выбранном каталоге. |
| `frontend` | `npm run lint` | Проверяет код по правилам линтера. |

Успешный запуск тестов завершается без упавших тестов. Для сборки и линтинга ориентируйся на отсутствие ошибок и код завершения `0`. В PowerShell код последней команды можно посмотреть через `$LASTEXITCODE`.

## Проверки в Docker Desktop

Используем Docker Desktop на Windows, чтобы периодически проверять почти готовые модули в окружении, приближенном к VPS. Планируем такой запуск ближе к завершению работы над модулем.

Из корня проекта при запущенном Docker Desktop:

```powershell
docker compose up -d --build
docker compose ps
```

Оба сервиса должны иметь статус `Up`. Backend доступен по адресу http://localhost:3000 и отвечает `Hello World!`. Frontend доступен по адресу http://localhost:8080 и показывает стартовую страницу со счётчиком.

Для проверки перезапуска выполни `docker compose restart` и снова открой оба адреса. Для остановки и удаления контейнеров и сети Compose выполни `docker compose down`. Собранные образы при этом сохраняются.
