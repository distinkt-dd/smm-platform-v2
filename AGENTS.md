# Работа над SMM Platform 2

## Начало работы

1. Проверь состояние рабочей копии через `git status --short --branch`.
2. Открой [карту проекта](docs/code-map/README.md) и выбери ветку по задаче. Начни с целевого документа и конкретных файлов. Переходи по связанным ссылкам по мере необходимости.
3. При ревью сверяй карту с изменённым кодом и его фактическими зависимостями. Если меняются контракт, точки входа, зависимости или проверки модуля, обнови его узел в том же изменении.

## Роли и ревью

- Дмитрий пишет код и выбирает архитектурное решение, когда нужен его выбор. Codex исследует варианты, готовит рекомендацию и записывает решение в документацию проекта.
- Codex ведёт документацию и доску, проводит ревью и выполняет доступные проверки. Дмитрий подключается к проверке, только если она требует недоступного Codex окружения или доступа. Подробности в [режиме проверок](docs/local-development.md).
- Ревью начинается с замечаний по убыванию приоритета. Для каждого замечания укажи файл и строку, условие возникновения, последствие и предложи исправление. Проверяй корректность, регрессии, границы модулей и достаточность проверок.
- После исправлений повторно проверь затронутое поведение. Если существенных замечаний нет, сообщи об этом и укажи, что проверено и какие сценарии остались без проверки.
- Сохраняй незавершённые изменения Дмитрия. Коммит выполняй по его явной команде после повторной проверки.

## Задачи в GitHub Projects

Работаем последовательно. Сначала закрываем общие архитектурные вопросы и доводим до готовности базовую настройку проекта. Затем берём прикладные модули по очереди, с учётом зависимостей. Согласованные архитектурные решения записываем в [docs/architecture.md](docs/architecture.md).

Каждый этап и модуль разбиваем на небольшие подзадачи. Одна рабочая карточка описывает один конкретный результат с понятным критерием готовности и способом проверки. Если в карточке несколько результатов, которые можно проверить по отдельности, выносим их в отдельные подзадачи. Следующую подзадачу берём после закрытия предыдущей, когда её зависимости выполнены.

По запросу Дмитрия Codex создаёт и обновляет задачи в [GitHub Issues](https://github.com/distinkt-dd/smm-platform-v2/issues) через подключение `github-issues`. Перед созданием Codex проверяет, есть ли такая задача, и указывает ожидаемый результат, критерии готовности и способ проверки. В рабочих карточках Дмитрия описываем изменения кода и конфигурации. Документацию и организационную работу выполняет Codex.

Если форма подтверждения не отображается, Codex проверяет, выполнилась ли операция в GitHub. Если записи ещё нет и Дмитрий уже поручил её сделать, Codex использует доступное подключение к GitHub API с правами на запись и проверяет результат. Если все доступные подключения требуют действия пользователя, Codex сообщает, какая операция осталась незавершённой.

Через `github-projects` Codex добавляет Issue на [доску SMM Platform 2](https://github.com/users/distinkt-dd/projects/2/views/1), выставляет согласованный статус и проверяет, что карточка появилась на доске. PR связываем с соответствующей задачей.

| Статус | Когда использовать |
| --- | --- |
| Можно брать | Задача описана, критерии готовности понятны, зависимости позволяют начать работу. |
| Взято в работу | Дмитрий начал выполнять задачу. |
| На ревью | Дмитрий передал изменения на проверку и приложил ссылку на PR или указал ветку. |
| Сделано | Ревью пройдено, согласованные проверки подтверждены. |

Когда задача проходит ревью, Codex сразу переводит её карточку из «На ревью» в «Сделано» через `github-projects` и проверяет новый статус на доске. Отдельная просьба Дмитрия о переносе карточки не требуется.

[Архитектурные решения](docs/architecture.md) фиксируют согласованный выбор Дмитрия. [Режим проверок](docs/local-development.md) описывает, когда использовать Docker Desktop.
