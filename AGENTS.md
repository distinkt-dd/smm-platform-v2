# Работа над SMM Platform 2

## Точка входа агента

Codex и DeepSeek Harness используют эту общую точку входа. Агент исследует варианты, готовит рекомендацию, ведёт документацию и доску, проводит ревью и выполняет доступные проверки. Дмитрий пишет код и выбирает архитектурное решение, когда нужен его выбор.

1. Проверь состояние рабочей копии через `git status --short --branch`. Незавершённые изменения Дмитрия сохраняются.
2. Открой [карту проекта](docs/code-map/README.md) и выбери ветку по задаче. Начни с целевого документа и конкретных файлов. Переходи по связанным ссылкам по мере необходимости.
3. В Codex используй доступные подключения `github-issues` и `github-projects`. В DeepSeek Harness используй подключение `github` — GitHub MCP Server, установленный бандлом `@local/dsh-github-mcp`. Его инструменты `mcp__github__*` покрывают задачи, комментарии, метки, пул-реквесты, репозитории и доски Projects V2. Проверь доступ вызовом `mcp__github__get_me`, состояние задач — `mcp__github__list_issues`. Резервный путь, если подключение недоступно, — CLI `gh` или REST/GraphQL с токеном из Git Credential Manager (`git credential fill` для `github.com`), переданным через `GH_TOKEN`.
4. В DeepSeek Harness токен лежит в `~/.dsh/.credentials.yaml` под именем `GITHUB_PERSONAL_ACCESS_TOKEN` и подставляется в подключение при запуске. Ему нужны права `repo` для задач и пул-реквестов и `read:project` вместе с `project` для [доски SMM Platform 2](https://github.com/users/distinkt-dd/projects/2/views/1). Если `mcp__github__projects_*` отвечает `404`, это нехватка прав, а не отсутствие доски: сообщи, что операция осталась незавершённой, и не подменяй её записью мимо GitHub.
5. При ревью сверяй карту с изменённым кодом и его фактическими зависимостями. Если меняются контракт, точки входа, зависимости или проверки модуля, обнови его узел в том же изменении.

Если доступ к GitHub или права токена не позволяют выполнить операцию, агент проверяет результат и сообщает, какая операция осталась незавершённой, вместо записи в обход GitHub.

## Роли и ревью

- Дмитрий пишет код и выбирает архитектурное решение, когда нужен его выбор. Агент исследует варианты, готовит рекомендацию и записывает решение в документацию проекта.
- Агент ведёт документацию и доску, проводит ревью и выполняет доступные проверки. Дмитрий подключается к проверке, только если она требует недоступного агенту окружения или доступа. Подробности в [режиме проверок](docs/local-development.md).
- Ревью начинается с замечаний по убыванию приоритета. Для каждого замечания укажи файл и строку, условие возникновения, последствие и предложи исправление. Проверяй корректность, регрессии, границы модулей и достаточность проверок.
- После исправлений повторно проверь затронутое поведение. Если существенных замечаний нет, сообщи об этом и укажи, что проверено и какие сценарии остались без проверки.
- Сохраняй незавершённые изменения Дмитрия. Коммит выполняй по его явной команде после повторной проверки.

## Задачи в GitHub Projects

Работаем последовательно. Сначала закрываем общие архитектурные вопросы и доводим до готовности базовую настройку проекта. Затем берём прикладные модули по очереди, с учётом зависимостей. Согласованные архитектурные решения записываем в [docs/architecture.md](docs/architecture.md).

Каждый этап и модуль разбиваем на небольшие подзадачи. Одна рабочая карточка описывает один конкретный результат с понятным критерием готовности и способом проверки. Если в карточке несколько результатов, которые можно проверить по отдельности, выносим их в отдельные подзадачи. Следующую подзадачу берём после закрытия предыдущей, когда её зависимости выполнены.

По запросу Дмитрия агент создаёт и обновляет задачи в [GitHub Issues](https://github.com/distinkt-dd/smm-platform-v2/issues) через GitHub API. Перед созданием агент проверяет, есть ли такая задача, и указывает ожидаемый результат, критерии готовности и способ проверки. В рабочих карточках Дмитрия описываем изменения кода и конфигурации. Документацию и организационную работу выполняет агент.

Если запись в GitHub не выполнилась из-за прав или авторизации, агент проверяет результат и сообщает, какая операция осталась незавершённой.

Агент добавляет Issue на [доску SMM Platform 2](https://github.com/users/distinkt-dd/projects/2/views/1) через API Projects V2, выставляет согласованный статус и проверяет, что карточка появилась на доске. PR связываем с соответствующей задачей.

| Статус | Когда использовать |
| --- | --- |
| Можно брать | Задача описана, критерии готовности понятны, зависимости позволяют начать работу. |
| Взято в работу | Дмитрий начал выполнять задачу. |
| На ревью | Дмитрий передал изменения на проверку и приложил ссылку на PR или указал ветку. |
| Сделано | Ревью пройдено, согласованные проверки подтверждены. |

Когда задача проходит ревью, агент сразу переводит её карточку из «На ревью» в «Сделано» через API Projects V2 и проверяет новый статус на доске. Отдельная просьба Дмитрия о переносе карточки не требуется.

[Архитектурные решения](docs/architecture.md) фиксируют согласованный выбор Дмитрия. [Режим проверок](docs/local-development.md) описывает, когда использовать Docker Desktop.
